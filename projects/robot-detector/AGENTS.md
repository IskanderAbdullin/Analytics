**Это не цепочка разовых поручений.** Сначала прочитай
[полное ТЗ автономной разработки](docs/AUTONOMOUS_RESEARCH_TZ.md),
[состояние и точный следующий шаг](research/autonomy_state.json)

Работай по циклу: проверяемая научная цель этапа → реализация →
negative/unit tests → commit/push без force → checkpoint с evidence
и NEXT_ACTION → **немедленно начинай следующий полезный этап в текущем
активном запуске**. Завершение одного этапа, CI green, PR, закрытие
узкого issue или отчет **не являются завершением исследования**.
Не выдавай пользователю промежуточные отчеты между этапами,
если не требуется сообщить о существенном блокере.

Подтверждение невозможного результата не заменяй оптимистичной
интерпретацией: сохраняй отрицательные данные и ограничения.
Если путь заблокирован, переходи к независимому научному этапу,
обновляй state и продолжай. Не изменяй чужие проекты.
Никакого обещания фоновой работы после конца сеанса без
действительно действующего планировщика. Перед вынужденной остановкой
оставь точный checkpoint для восстановления.

Этот файл относится **только** к `projects/robot-detector/`. Проект независим от IPO Analytics.

## Строгие ограничения

1. НЕ менять `src/ipo_forecast/`, существующие Python модели/CLI IPO, `pyproject.toml` корневого IPO проекта и текущие источники данных IPO, если отдельного явного запроса нет.
2. НЕ внедрять торговую функциональность. Работать только с обезличенными публичными рыночными данными, read-only потоками, локальным replay и экспортом аналитики. Не запрашивать доступ к счетам, портфелю или заявкам.
3. НЕ выводить «N настоящих роботов/владельцев»: только различимые алгоритмические паттерны с неопределённостью и исследовательским объяснением. Не приписывать стороне пассивной заявки направление потока без проверки семантики провайдера.
4. НЕ помещать в коммиты токены, сырые рыночные архивы с сомнительной лицензией, реальные торговые персональные данные. В .gitignore проекта исключить data/raw, data/normalized, data/results, .env, traces и build artifacts.
5. Все эмпирические метрики привязать к конкретной выборке/seed/версии модели, не выдумывать confidence и backtest.
6. Сначала воспроизводимая baseline и stage-2 validity, потом streaming и ML. Сложный модуль не должен переписывать общий data contract без версии и теста миграции.
7. Не добавлять runtime dependency на OsEngine в Core. Адаптер OsEngine отдельный и опциональный.
8. Существующие данные и ошибки не исправлять «молчаливой очисткой»; quarantine + coverage flags + provenance.

- В отчёте указывать branch, commit SHA, запущенные проверки, результаты, незакрытые вопросы и что **не** тестировалось.

- Перед живым подключением проверять актуальную документацию провайдера и отсутствие методов торговли.

## Приоритет задач

1. Stage 1: data schema, history import, normalization, fixed-volume cadence, no-double-count, CLI/reports.
2. Stage 2: null models, synthetic truth, blinded calibration, forecast scoring.
3. Stage 3: robust T-Invest stream, UI, API and optional OsEngine adapter.
4. Stage 4: variable TWAP, book heuristics, model comparison, metaorder experiments.

Если source capability недоказана, помечать `BLOCKED_BY_DATA`, описывать альтернативы и продолжать независимые synthetic tests; не объявлять работу завершённой без проверок.

## Обязательные ограничения новых ABIDES/L2 исследований (21.11.2026)

- У каждого `aggregate` из публичного L2/print-исследования должен быть
  строгий **список разрешённых полей JSON**. Любые дополнительные поля,
  включая `agent_id`, `private_truth`, исходные записи событий или
  произвольные метаданные, считаются нарушением и вызывают ошибку.
  Нельзя выгружать сырые L2 архивы или внутренние имена/ID агентов в
  GitHub artifacts. Допустимы только агрегированные количества
  controlled synthetic fills после завершения публичных признаков.
- Сверять содержимое полных L2 snapshot последовательностей и
  публичных принтов через нормализованный `public_tape_fingerprint`
  для каждой аналитической фазы, а не через одну сумму print count
  или SHA исключительно сделок. Старые исследования **не**
  получают ретроспективного подтверждения полноты L2.
- Для сравнения фаз использовать **один исходный seed×scenario market
  run** как одну экспериментальную единицу. Три аналитические фазы
  одной ленты — три **зависимых представления**, а не три рынка.
  Пересечение диапазонов, смена знака и явное отсутствие L2 coverage
  должны отражаться в явных предупреждениях; не выбирать фазу
  по найденной точности и не выставлять реальный confidence.
- Для фонового и контрольного TWAP рынка с одинаковым random seed
  нельзя вычитать public event streams один к одному и утверждать,
  что полученная разность — исполнившиеся сделки контролируемого
  робота: рынок и стакан меняются **эндогенно**.
- После успешной первоначальной симуляции дорогой workflow менять
  на `workflow_dispatch` и сохранять
  **только дешёвые deterministic source tests** в автоматическом
  исследовательском CI. Прежние использованные seeds не являются
  новыми blind data при повторном запуске.

## Контроли на реальной публичной ленте: split fills и nulls

- Для проверки односторонних интервалов на сделках сначала учитывать,
  что **несколько принтов одного исполненного рыночного ордера могут
  иметь одинаковый exchange timestamp**. Независимая перестановка
  стороны каждого принта разрушает структуру исполнения и не
  является адекватным нулевым рыночным процессом.
- `public_trade_direction_null.py` поддерживает **два строго
  разных исследовательских контроля**:
  (а) слабый — перемешивание направлений отдельных принтов
  внутри UTC-минуты; (б) более консервативный — перемешивание
  целых векторов сторон одновременных принтов только между
  группами одинаковой мощности той же UTC-минуты.
- Оба контроля сохраняют исходные timestamp-позиции,
  количество и стороны сделок внутри минуты, не импортируют
  order book L2 или реальные private IDs и не дают p-value,
  FDR, точности распознавания роботов или разрешения
  на коммерческую торговлю.
- 18/19 ноября LTCUSDT — **уже просмотренные** данные.
  Любое новое сравнение с ними — ретроспективное развитие
  методов, а не независимый слепой тест качества.
- Публиковать только крошечные агрегаты с контрольными
  суммами провайдера и ссылкой на воспроизводимый код.

## Обязательная репликация при разной ликвидности рынка (21.11.2026)

- Печатный поток сделок на Binance (SPOT) **не является историей
  полного стакана L2**, не даёт реальных владельцев/родительских
  заявок и не калибрует FDR детектора.
- **Один-единственный публичный принт в 30-секундном интервале
  автоматически всегда односторонний**, независимо от алгоритма.
  Условия заполненности интервалов и фиксированную 0/10/20
  временную сетку определять **до** загрузки новой выборки.
- При тестировании на разных инструментах удерживать
  **отрицательные результаты**. Для BCHUSDT 17/18/20 ноября
  2026 исходная 0-секундная оценка one-sided среди интервалов
  c >=5 принтами не превышает максимума 8 консервативных
  null-перестановок; 19 ноября превышает только на 2 интервала.
  Нельзя выбирать удачную фазу 20s вместо 0s и объявлять
  практическое распознавание робота.
- Разделять источники **изначально просмотренные**, отдельно
  пререгистрированные неизученные архивные даты и новые
  forward-time данные. Разные инструменты в одну дату
  не означают независимые режимы рынка.
- Новые реальные исходные архивы разрешены только для
  некоммерческого исследования в рамках Binance Vision Terms;
  хранить только компактные source_sha/aggregate JSON,
  никогда не делиться сырыми event-векторами.

## Исторический NASDAQ L2-демообразец: отдельный правовой шлюз

- Официальный LOBSTER архив AMZN 2012-06-21, 10 уровней, можно
  проверять на **формат/синхронность событий и книги** как
  явно предлагаемый демонстрационный образец.
- **Уточнение по демонстрационным файлам:** LOBSTER сам
  публикует бесплатные образцы `message` + `orderbook`,
  описывает научную работу с ними и предоставляет демо-код.
  Отдельные договорные условия относятся к **подписке**,
  а не автоматически устанавливают запрет на некоммерческое
  исследование свободно скачиваемого демо-образца.
- **Не блокировать исследование/разработку алгоритма** на этом
  публичном демо исключительно из-за отсутствия договора на
  платную подписку. Можно проводить воспроизводимые научные
  эксперименты и публиковать собственный исходный код, отчёты,
  собственные графики и агрегированные метрики с атрибуцией
  LOBSTER и NASDAQ.
- Разделять это с **публикацией оригинального архива/строк**,
  поставкой коммерческих торговых сигналов и доступом к
  **дополнительным платным** наборам данных: их условия
  проверять отдельно. Не заявлять, что отдельная лицензия
  обязательна для любых экспериментов с публичным демо;
  но и не утверждать, что у него точно есть лицензия на
  любое коммерческое/публичное повторное распространение.
- Не перепутать `direction=-1` в LOBSTER `message`:
  это сторона *пассивной лимитной заявки*. Если event=4,
  направление агрессора **противоположно**.
- Файл `orderbook` — состояние *после* соответствующей
  строки `message`. Только 10 занятых уровней,
  это не весь стакан и не восстановление реальных
  физических участников.
- У производителя **нет публично подписанной SHA256**
  для демонстрационного архива. Локальный digest
  не подтверждает полноту или аутентичность.
- Сохранять только размер и исходные агрегаты,
  ни одну сырую строку с order ID, book snapshot
  или непроверенной лицензией в GitHub не выкладывать.
