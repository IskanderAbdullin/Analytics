# RD-L2-RESEARCH-01: реальные event-time признаки стакана NASDAQ (AMZN)

## Результат и воспроизводимость

Прежний этап проверял только целостность **269 748** пар
«сообщение / 10-уровневый стакан после сообщения».
Новая стадия добавила исследовательский read-only
потоковый анализ истории событий и проверила его
на синтетических негативных сценариях и затем
на исходном историческом демофайле биржи NASDAQ
за 21 июня 2012 г. через LOBSTER.

**[Оригинальный успешный запуск GitHub Actions #44925498585](https://github.com/IskanderAbdullin/Analytics/actions/runs/44925498585)**:
стандартизованные тесты и одна исходная повторная
загрузка демонстрационного архива. Зафиксированный ранее
локальный SHA-256 ZIP совпал, но **это не официально
подписанная провайдером контрольная сумма**.

[Исходный научный протокол](../research/lobster_event_time_protocol_20261121.json)
был закоммичен до повторного расчёта признаков. Поскольку
этот же датасет уже использовался для QA, это
**ретроспективная описательная статистика**, а не новый
слепой набор для валидации детектора.

## Семантика — почему это не идентификация робота

1. В \`message\` LOBSTER направление лимитной заявки
   **пассивное**. Если event=4 и resting side=-1,
   это агрессивная покупка, а не агрессивная продажа.
   Скрытые исполнения event=5 считаем отдельно.
2. Строка \`orderbook\` соответствует состоянию
   **после** данного события. Для оценки перехода
   сравнивается предыдущий post-event стакан с текущим.
   Такое сравнение **не доказывает причинный эффект**
   текущего сообщения: эндогенный поток событий и
   одинаковые timestamps усложняют интерпретацию.
3. Средние выше **взвешены по событиям**, а не
   по календарному времени. Если в периоде с узким
   спредом было больше событий, он сильнее влияет
   на итоговую оценку. Следующий этап #76
   отдельно измеряет ошибку такого взвешивания.
4. Демо отражает **одну историческую сессию 2012 г.**,
   только 10 занятых уровней на сторону, без
   реальных идентичностей владельцев или labels роботов.
   Нельзя заявлять true-positive rate, p-values
   или false-discovery rate по исходной ленте.
5. Публичное демо LOBSTER используется для
   **некоммерческой научной работы**. Программный код,
   методика и агрегированные результаты открыты.
   Сырые CSV/ZIP, order references и event-time
   ряды не перепубликуются.

## Технические результаты

- [Анализатор](../tools/lobster_event_time_features.py)
  в одном bounded архивном replay вычисляет частоты
  событий, межсобытийные интервалы, группы совпадающих
  timestamps, состояние top BBO, spread/depth/imbalance,
  изменения котировок и привязку к passive-side
  семантике.
- [Негативные тесты](../tests_background/test_lobster_event_time_features.py):
  пустые/повреждённые входы, ряд с одинаковым временем,
  изменение только глубины, изменение только цены,
  отсутствие стакана, невозможность незаметной утечки
  order reference IDs в агрегаты, ограничения памяти.
- Выходной JSON валидируется по точному
  списку разрешённых полей; исходные строки или серии
  отдельных timestamp/цен не экспортируются.
