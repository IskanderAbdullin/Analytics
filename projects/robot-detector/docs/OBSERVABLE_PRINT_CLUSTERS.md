# A second observation unit: traceable clusters of public trade prints

**Status:** independent experimental read-only C# model, 19 November 2026. **Not an identifiable parent-order, bot-owner or order reconstruction system.** The original public tape remains immutable; no source print is deleted or silently deduplicated.

## Motivation

Timestamp-quality analysis of public T-Invest archives on 2026-11-18 showed that a substantial fraction of public rows share an exact `TRADE_TS` with other rows: **32,311/83,515** SBER prints and **5,902/10,584** MOEX prints. The single largest exact timestamp group contained up to 217 public rows (SBER). However, same-time rows can come from multiple unrelated market participants, partial fills, simultaneous executions or vendor timing granularity.

Read [TIMESTAMP_QUALITY_AUDIT.md](TIMESTAMP_QUALITY_AUDIT.md) for the exact method and evidence. Relevant open-source/academic context: [Reconstruction of Order Flows using Aggregated Data](https://arxiv.org/abs/1604.02759) investigates recovery of detailed order flows from public aggregated information. It does **not** imply that our publicly observed same-time/same-price group identifies one agent. T-Invest archive contract: https://developer.tbank.ru/invest/services/history-md/head-history-md .

## Opt-in derived representation

`src/RobotDetector.Core/ObservablePrintClusters.cs` builds a **separate projection**, grouping source public records only when all of these fields are *exactly identical*:

- instrument UID;
- public trade source (EXCHANGE vs DEALER);
- provider-reported BUY/SELL direction (including UNKNOWN as its own grouping);
- trading mode and reported session;
- full exact UTC timestamp (`DateTimeOffset.Ticks` at its originally parsed 100ns representation);
- exact public price (no tolerance, no tick rounding).

Within each group, sum quantities in lots with checked arithmetic, count original rows, retain **every original EventId**, and assign a deterministic `CLUSTER_<sha>` identifier. Different price, time, side, mode, source or session MUST NOT be merged.

One source row maps to exactly one observable cluster; group membership must remain auditable through the original print IDs. Total public print count (source) and total lots (source/derived) are checked. The derived `TradeImportResult` receives an explicit source label `DERIVED_PUBLIC_PRINT_CLUSTER`, a separate deterministic source-provenance hash and inherits the original feed coverage flag **without upgrading its certainty**.

The derived tape may be passed to the existing exact-volume `PeriodicDetector` to compare whether candidate cadence counts change when the **observation unit** changes. Both models remain uncalibrated. This is a sensitivity study, **not** evidence of successful order reconstruction or improved future prediction.

## CLI and example

```powershell
cd projects/robot-detector

dotnet run --project src/RobotDetector.Cli -- cluster-compare \
 --input fixtures/synthetic_split_clips_5s.csv \
 --min-matches 6 --output data/results/cluster-compare.json
```

The synthetic example has **14 public rows** (two different clip quantities at each of seven consecutive timestamps, separated by 5 seconds), the **same price and source**. Its seven derived clusters each sum to 100 lots. Expected result on this deliberately constructed synthetic tape:

| Observable unit | Number of events | Historical fixed-q cadence candidates |
|---|---:|---:|
| Original anonymous print rows | 14 | 0 |
| Derived exact-time/price/side clusters | 7 | 1 |

Total public lots remain **700**. This **does not** mean one robot was identified: even the artificial data could be generated by unrelated accounts without privileged identity labels. The two candidate counts use **different event definitions** and must not be directly interpreted as bot-count improvements.

## Required gates

1. Same-time/same-price/same-side example: every original source EventId maps exactly once; no lots lost or generated.
2. Source/side/mode/session/price differences prevent grouping.
3. Stable synthetic derived IDs independent of input row order; **duplicate original source IDs must throw**.
4. If full public time/price attributes match but the economic trades truly come from different actors, the derived view cannot detect that; this is a **known non-identifiability limitation**.
5. Controlled synthetic split clips may reveal a derived cadence absent in the row-level view; negative synthetic controls must be added before calling this statistically predictive.
6. Real-data smoke for **SBER_TQBR and MOEX_TQBR, 2026-11-18** on the already inspected public files, using the same read-only historical adapter. This is reused development data, NOT a fresh held-out statistical validation. Record only counts/hashes, source-vs-derived candidate count, total lots and uncertainty flags.
7. Real UI/live trading and confirmation of physical bot programs remain blocked until stronger nulls, known-agent simulated ground truth and independent forward prediction tests pass.

**Results:** append only after the CI run has succeeded. No raw market tape or evidence mapping is uploaded as a GitHub artifact.
