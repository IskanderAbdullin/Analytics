# RD-ROBUSTNESS-04 — качество исходных L2 и режим воздержания от вывода

## Главная научная ошибка, которую предотвращает этап

**Совпадение числа строк event и book, правильная контрольная
сумма ZIP и даже отсутствие пропусков в видимых идентификаторах
заявок не доказывают, что все события биржевого matching engine
попали в исследовательскую выборку.** Публичный order reference
не равен счётчику всех событий.

При недоказанной полноте источника нельзя делать вывод
«в этой записи роботов нет» только потому, что не выявлено
сигналов или вообще отсутствуют биржевые события.

Разработан [строгий synthetic observability/abstention
gate](../tools/public_l2_feed_coverage_gate.py). Он
требует помечать источник как:

- **\`SYNTHETIC_COVERAGE_ELIGIBLE_ONLY\`** —
  только если контролируемый синтетический oracle
  предоставляет достоверные ожидаемые границы
  *номеров событий*, и все события, времена и paired
  L2 подтверждены внутри заданного испытания.
  Это **не право утверждать полноту реальной биржи**.
- **\`UNKNOWN_SOURCE_COMPLETENESS\`** —
  непрерывное наблюдение без внешнего сертификата
  числа и границ событий, либо исходный поток
  вовсе не имеет отдельного sequence. Это типичная
  научно честная категория для неизвестного реального
  источника.
- **\`ABSTAIN_SOURCE_OR_BOOK_INTEGRITY\`** —
  обнаружены пропуск/дубликат/перестановка
  последовательности событий, нарушение порядка
  времён, несинхронный стакан, отсутствующая котировка,
  crossed/locked BBO или интервал удержания прежней
  котировки свыше фиксированных 30 секунд.

### Установленный контрпример

Пять синтетических событий с source sequence
200–204, ровно пять aligned post-event L2
обновлений и заранее известными oracle границами:
**1,0 coverage** и synthetic-only eligibility.

Удаление одного события при тех же oracle
границах даёт **4/5 = 0,8** и explicit
\`GAP_IN_OBSERVED_EVENT_SEQUENCE\`, то есть
**ABSTAIN**, а не оценку отсутствия роботов.

Даже пять наблюдаемых событий с последовательными
ID без внешней аттестации истинных границ
остаются **UNKNOWN**, потому что отсутствующие
в начале/конце исходного потока сообщения
по самой наблюдаемой ленте обнаружить нельзя.
Если в наблюдаемом диапазоне появляются
лишние неизвестные ID, coverage никогда
не может стать больше единицы.

### Негативные проверки

[Негативные тесты](../tests_background/test_public_l2_feed_coverage_gate.py)
моделируют:
- дублированный, отсутствующий, переставленный
  либо частично скрытый source-event sequence;
- разорванный или несинхронный paired book;
- отсутствующий bid/ask и locked/crossed quote;
- большой интервал удержания previous quote
  при целой нумерации событий;
- timestamps в неверном порядке, одновременные
  события без ложного gap;
- некорректную/слишком большую oracle границу
  и подмену source order reference на event sequence.

[Дешёвый научный CI #44926821602](
https://github.com/IskanderAbdullin/Analytics/actions/runs/44926821602)
успешно запустил проверки без загрузки
каких-либо реальных биржевых архивов.

## Ограничения gate

Это **synthetic-only** gate. Он не превращает
LOBSTER AMZN 2012 или Binance Vision
в удостоверенно полную историю matching engine.
Котировки LOBSTER pair с сообщением не содержат
универсального event sequence attestation,
а ZIP SHA256 у демо рассчитан только локально.
30-секундная граница — осторожное
предварительное правило для текущей модели,
а не биржевой стандарт обнаружения простоев.

Статусы source/provenance, paired L2 coverage,
sequence completeness и реальная разметка
торговых алгоритмов — четыре разные
величины. Нельзя подменять ими друг друга
или объявлять calibrated real-market FDR.

Не использованы реальные частные account ID,
стаканы/сделки не выгружены. Следующий этап:
[воспроизводимость всего research stack без
закрытых данных](https://github.com/IskanderAbdullin/Analytics/issues/80);
master goal #72 остаётся открытым.
