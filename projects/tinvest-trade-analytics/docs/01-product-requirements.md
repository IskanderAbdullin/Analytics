# 01. Продуктовое ТЗ и функциональные требования

Версия 1.0 · дата: 2026-11-18. Режим: персональная локальная аналитика собственной торговли.

## 1. Миссия

Построить независимую платформу, в которой можно доказательно ответить: «сколько заработано за период, на чём, каким роботом, какой ценой исполнения, с каким риском, при каких рыночных условиях и насколько этот результат воспроизводим?». Приоритет — корректная бухгалтерия и сохранность данных, затем удобство и масштаб аналитики, далее прогнозные модели.

### 1.1 Ключевые сценарии

- **UC-01** — указать read-only токен T-Invest, обнаружить свои счета, выбрать период, импортировать полную историю, сохранить прогресс при сбое.
- **UC-02** — за секунды открыть P&L по любому дню, неделе, месяцу, произвольному UTC/биржевому интервалу с учётом пред/после комиссий и налогов.
- **UC-03** — открыть инструмент (например, бессрочный фьючерс), увидеть историю сделок, вариационной маржи, фандинга, среднюю/ FIFO себестоимость, комиссии и движение результата по дням.
- **UC-04** — выбрать конкретного робота/стратегию/версию/сессию, отделить его заявки от ручной торговли на том же инструменте и счёте.
- **UC-05** — на основании журнала OsEngine / собственной телеметрии измерить задержки, перестановки, частичные исполнения, проскальзывание, долю пассивных исполнений, заработок по уровням стакана.
- **UC-06** — сверить отчётность с брокерским отчётом и остатками, увидеть **конкретные** несопоставленные события и причины расхождения.
- **UC-07** — выбрать сложный период (например, 09–15.11.2026) и исключить 14.11 без искажения недельной суммы, с точным правилом торгового дня.
- **UC-08** — сравнить робот A и робот B по одинаковым инструментам, временам, рыночному режиму, размеру позиции и одинаковой версии методологии.
- **UC-09** — экспортировать сырые операции, производные таблицы, отчёт и трассу расчёта в CSV/Parquet/JSON/Excel; восстановить отчёт по сохранённому run_id.
- **UC-10** — обучить офлайн-модель аномалий исполнения или прогнозирования условного результата на исторических point-in-time данных, проверить walk-forward и сравнить с наивной базовой моделью.
- **UC-11** — анализировать общий результат всех своих счетов, с нейтрализацией внутренних переводов.
- **UC-12** — спросить через локальный аналитический API или подключённый MCP «P&L по NVDAperpA за прошлую неделю без 14-го», получить методологию, степень полноты, суммы и ссылки на первичные события.

### 1.2 Пользователи

Основной: владелец нескольких торговых стратегий и счётов, одновременно ведущий ручную торговлю и разработку OsEngine/C# роботов. Возможные дополнительные роли: только просмотр, исследователь (обезличенные выгрузки), разработчик адаптера. Многопользовательский облачный SaaS на старте исключён.

## 2. Границы / non-goals

В v1 нет выставления/отмены заявок, копитрейдинга, автоматического принятия торговых решений, обещаний доходности, налоговой декларации «под ключ» и биржевого data feed реселлинга. Бухгалтерские/налоговые оценки носят аналитический характер, официальные суммы подтверждаются брокерской документацией. Не использовать API с ключом торговли там, где допускается ключ только для чтения.

## 3. Функциональные требования (FR)

### 3.1 Управление данными

- **FR-D001 [P0]** Брокерские источники должны реализовывать `IBrokerAdapter` с capabilities discovery: accounts, historical operations, order fills, balances, portfolio snapshots, broker reports, instrument metadata, market data.
- **FR-D002 [P0]** Импорт с пагинацией, checkpoint, дедупликацией, retry/backoff, deadline, rate-budget с учётом общей квоты пользователя и параллельных роботов.
- **FR-D003 [P0]** Полный исторический backfill, скользящая повторная загрузка последних N дней, выборочная пересверка старых периодов, ручной re-sync.
- **FR-D004 [P0]** Исходные ответы + запрос и метаданные сохранять неизменяемо; нормализованные таблицы версионировать.
- **FR-D005 [P0]** Импорт CSV, XLSX и брокерского отчёта с предпросмотром схемы, явным mapping и quarantine неизвестных полей.
- **FR-D006 [P0]** Хранить идентификаторы инструментов (UID/FIGI/ticker/class_code), алиасы и исторические спецификации, не использовать ticker как уникальный ключ.
- **FR-D007 [P0]** Доступность данных описывать coverage по счёту/инструменту/интервалу/типу (fills, ops, quotes, orderbooks, logs).
- **FR-D008 [P1]** Подключать другие брокеры через плагины без изменения расчётного ядра.
- **FR-D009 [P1]** Поддерживать ручное подтверждённое исправление привязок / классификаций как отдельный audit trail, не правя сырьё.
- **FR-D010 [P1]** Снапшоты EOD, T+0/T+1/cash/market-value и детерминированный rebuild.

### 3.2 Финансовый результат

- **FR-P001 [P0]** Отдельно реализованный P&L, unrealized P&L, total economic P&L, cash-flow effect, fees, taxes, gross/net; не показывать один «прибыль» без определения.
- **FR-P002 [P0]** FIFO и weighted-average accounting для акций/ETF/облигаций, short и long, partial close и flip; выгружать лоты.
- **FR-P003 [P0]** Фьючерсы: начисленная/списанная variation margin, открытая переоценка от расчётной базы, экспирация, правила контрактной стоимости, funding без double count.
- **FR-P004 [P0]** Расходы: брокерские, биржевые, депозитарные, заём/маржа, овернайт, распределяемые и общесчётные; отчёт до и после расходов.
- **FR-P005 [P0]** Внешние пополнения/выводы и внутренние переводы не считать trading P&L.
- **FR-P006 [P0]** FX conversion c timestamp, rate source, missing-rate flag; показывать результат в валюте актива и базовой валюте, P&L конвертации отдельно.
- **FR-P007 [P0]** Дневные результаты с явным выбором calendar day, exchange trade date, clearing day и time zone.
- **FR-P008 [P0]** Воспроизводимый расчёт с versioned algorithm, settings hash, as_of и data snapshot.
- **FR-P009 [P1]** Денежная доходность TWR / XIRR при корректных потоках, отдельные gross/net и currency-adjusted показатели.
- **FR-P010 [P1]** Доходность и вложенный капитал по стратегии, риск/капитал/ГО для срочных инструментов, без некорректного использования «покупной стоимости».
- **FR-P011 [P1]** Дивиденды, купоны, НКД, амортизация, корпоративные действия, налоги и корректировки.
- **FR-P012 [P2]** Опционы с премией/экспирацией/исполнением, стоимость контрактов и greeks при наличии рыночных данных.

### 3.3 Аналитика торговли

- **FR-A001 [P0]** Таблица по дате/инструменту/счёту/роботу: P&L, комиссии, оборот, объём, количество исполнений, средняя цена, coverage и reconciliation status.
- **FR-A002 [P1]** Журнал позиций/сделок, интерактивная шкала входов/выходов, фильтры, drill-down до операции и сырого объекта.
- **FR-A003 [P1]** Win rate, expectancy, payoff ratio, profit factor, max drawdown, rolling return, volatility, Sharpe/Sortino (с явными допущениями).
- **FR-A004 [P1]** Анализ по активу, классу, бирже, времени суток, дням недели, направлению, размеру, ликвидности, режиму рынка и роботу.
- **FR-A005 [P1]** MAE/MFE для round trips при доступном intratrade market data, holding time, entry/exit quality.
- **FR-A006 [P1]** Сравнение стратегий и версий бота (объективные критерии, контроль объёма и условий рынка).
- **FR-A007 [P1]** Аналитика качества исполнения: decision/arrival price, VWAP/TWAP benchmark, slippage, spread capture, adverse selection, fees/rebates.
- **FR-A008 [P1]** Для маркетмейкинга — inventory P&L, spread P&L, risk exposure, quote lifetime, cancel-to-fill, book-depth/target-level stats.
- **FR-A009 [P1]** Обнаружение аномалий: несогласованная сделка, скачок комиссии, непонятная маржа, внезапное расхождение портфеля.
- **FR-A010 [P2]** Отчёты по годам, налоговым периодам, стратегиям и исследовательским экспериментам.
- **FR-A011 [P2]** Интерактивное сравнение «что было бы при другом правиле выхода» — исключительно offline counterfactual с оговоркой о недостоверности ненаблюдаемых исполнений.

### 3.4 Роботы и интеграции

- **FR-R001 [P0]** Каждому робот-сигналу/заявке присвоить `strategy_id`, `bot_id`, `bot_version`, `run_id`, `client_order_id` и correlation_id когда информация доступна.
- **FR-R002 [P0]** Система отдельно хранит `attribution_status`: exact / inferred / manual / unknown; строго запрещено по умолчанию считать все сделки по инструменту сделками одного робота.
- **FR-R003 [P1]** Адаптер событий OsEngine: submit/cancel/replace/ack/fill/reject, position-change, strategy-decision, orderbook snapshot, robot health.
- **FR-R004 [P1]** Повторное воспроизведение одной сессии робота на временной шкале, reconciliation заявок с executions и операциям брокера.
- **FR-R005 [P1]** Конфликты между ручной торговлей и роботами на одном счёте должны разрешаться явно, с метрикой нераспределённого P&L.
- **FR-R006 [P2]** Универсальный plugin SDK для иных торговых терминалов и Python-роботов.
- **FR-R007 [P2]** Локальный read-only MCP/API с скоупами, лимитами и защитой финансовых данных.

### 3.5 UI / удобство

- **FR-U001 [P0]** Состояние синхронизации по каждому счёту; прогресс по страницам/датам; ошибки и кнопка корректного повтора.
- **FR-U002 [P0]** Dashboard с выбором интервала, time zone, базовой валюты, accounting method и уровня gross/net.
- **FR-U003 [P1]** Детализация суммы: сумма → инструмент → день → операции → сырой payload.
- **FR-U004 [P1]** Сохраняемые пользовательские фильтры, таблицы, пресеты и конфигурации отчётов.
- **FR-U005 [P1]** Экспорт CSV, JSON, Parquet, XLSX, видимый watermark качества данных.
- **FR-U006 [P1]** График Equity, P&L by day, rolling risk, карта доходности, графики роботов, trace execution.
- **FR-U007 [P1]** Работа офлайн на последнем локальном snapshot; никогда не показывать stale данные как live.
- **FR-U008 [P2]** Поиск по тикеру/UID/сигналу/заявке, сохранение отчёта как локальный URL/API resource.

## 4. Нефункциональные требования (NFR)

- **NFR-01 Безопасность:** read-only token, OS secure vault, шифрование секретов, redaction логов, deny-by-default, отсутствие Order/Post methods в production dependency graph, экспорт с маскировкой счёта.
- **NFR-02 Целостность:** транзакционность импорта, unique constraint по внутренним ключам, checksum, WAL, checkpoint, резервные копии + восстановление.
- **NFR-03 Аудит:** отчёт содержит `calculation_run_id`, версию модели и данные источников; повтор того же набора даёт тот же результат.
- **NFR-04 Точность:** decimal/целочисленные денежные минимальные единицы, без IEEE754 float для денежных балансов; строгие правила округления по валюте/контракту.
- **NFR-05 Производительность (целевые KPI, не обещания):** 1 млн нормализованных исполнений локально, tabular day report за 2–5 сек на современной SSD-машине после индексации; инкрементальная синхронизация без полного rebuild; profiling в CI.
- **NFR-06 Надёжность:** разрыв связи, дубликат страницы, падение посреди batch не портят агрегаты; повтор безопасен; fallback при временной недоступности API.
- **NFR-07 Ресурсы:** память и disk quota конфигурируемы, фоновые операции low priority; не мешать торговым роботам на одной машине.
- **NFR-08 Доступность:** работа Windows в приоритете, независимый headless CLI, доступ к отчётам без постоянного соединения.
- **NFR-09 Тестируемость:** unit/integration/contract/property/golden/master-data tests с фикстурами, CI в PR.
- **NFR-10 Лицензии:** проверка совместимости OSS, отсутствие закрытых рыночных данных в репозитории, соблюдать запрет на ретрансляцию T-Invest data.
- **NFR-11 API evolution:** versioned contracts, миграции без потери истории, стратегия backwards compatibility.
- **NFR-12 Интеграции:** ограничение API и квота применяются ко всем счетам и токенам пользователя; общий quota-budget в конфигурации.

## 5. Результаты / артефакты, необходимые на каждом этапе

Код + читаемый ADR + миграция БД + тестовые фикстуры + набор passing tests + журнал ограничений и известных расхождений + пример CLI + документация/скриншот UI (если применимо) + commit hash. Ни один milestone не принимается лишь по наличию исходников.

## 6. Ключевые риски

- Несовпадение operation IDs между загрузками; mapping торговых исполнений недоступен без дополнительных данных.
- В некоторых торговых операциях не хватает связки с order ID или robot ID.
- Исторический orderbook может отсутствовать или быть неполным — недопустимо выдумывать fill/slippage.
- Фьючерсы/вечные контракты/опционы требуют контрактной стоимости, клиринга, funding и ценообразования.
- Исторический total P&L без котировок/снапшотов неполон.
- В мультисчётной системе внутренний перевод может выглядеть как внешний до сопоставления обеих сторон.
- Для налогового P&L официальная методология и документы имеют приоритет над аналитической.
- Неоднозначная оценка риска стратегии при переменном ГО/плече.

**Порядок решений:** все неопределённости явно документировать в `docs/08-sources-and-decisions.md`, не замалчивать и не подменять неизвестное оценкой без метки.
