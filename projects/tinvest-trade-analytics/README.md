# TInvest Trade Analytics — проектное ТЗ

**Статус:** ТЗ v1.1 + начальная реализация v0.1 (18.11.2026). Обязательно смотреть [статус и ограничения реализации](docs/11-implementation-status.md); BROKER_VALIDATED пока нет. **Язык:** русский. **Тип:** отдельный проект в монорепозитории Analytics.

## Цель

Локальная, расширяемая, проверяемая исследовательская платформа персональной торговли: полный импорт событий брокера, учёт капитала и P&L по акциям/фондам/облигациям/фьючерсам/опционам/валютам, attribution по конкретным роботам и стратегиям, аналитика качества исполнения, риска, стакана, экспериментов и в перспективе ML. Первым брокером служит T-Invest. Торговля или отправка заявок из аналитической программы **не предусмотрены**: только чтение, расчёт и исследование.

**Не путать:** `projects/robot-detector` — отдельная задача выявления алгоритмической активности в публичном потоке. В этой папке строится учёт **собственной** торговли и результатов своих роботов. При необходимости проекты будут обмениваться только версионированными датасетами и контрактами.

## Инварианты проекта

1. **Первичные данные не уничтожаются и не подменяются:** сохраняем сырой ответ API вместе со временем получения, источником, запросом, версией схемы и хешем; корректировки создают новые ревизии.
2. **Воспроизводимость:** каждая цифра P&L раскрывается до исходных операций, рыночных оценок, алгоритма, версии и правил FX/календаря.
3. **Истина не единична:** реализованный P&L, total-return, денежный P&L, результаты до/после расходов и до/после налогов — независимые, подписанные метрики.
4. **Никакого двойного учёта:** комиссия, вариационная маржа и фандинг должны учитываться один раз на основании типов операций и сверки.
5. **Неизвестное не равно нулю:** при неполных данных результат помечается `provisional`, `partial`, `unreconciled`, а не объявляется точным.
6. **Счет / инструмент / робот — разные сущности:** брокерская операция не всегда содержит достоверную идентичность робота. Attribution при отсутствии связи помечается неизвестным.
7. **Нет утечки будущего:** любые ML-признаки доступны только на момент принятия решения; фиксируются event time, observed time, available time.
8. **Безопасность:** токен read-only в системном защищённом хранилище, секреты, номера счетов и личные данные не публикуются; никакого Computer Use без отдельного явного согласия.
9. **Никаких приказов брокеру:** ни на одном этапе программа не должна выставлять, изменять или отменять торговые заявки.
10. **Отделение аналитики от роботов:** подключение к OsEngine — опционально, счёт работает и без него.

## Предлагаемый технологический стек

- `C#/.NET 10`: домен, ingestion, API, CLI, детерминированный расчёт.
- `SQLite` локально на старте (WAL, резервные копии, миграции), модульная абстракция хранения; Parquet / DuckDB для исследования; возможность PostgreSQL позднее.
- Desktop UI — `Avalonia` (кроссплатформенность) или `WPF` (если приоритет только Windows); окончательно выбрать в ADR до разработки UI. Backend не зависит от UI.
- `Python` отдельным процессом/пакетом для исследований и ML; без доступа к брокерским токенам.
- Тесты xUnit/FluentAssertions либо эквивалент, property-based тесты, contract tests, CI; структурированные логи OpenTelemetry-совместимого формата.
- SDK/протокол — после проверки актуальной версии официальных контрактов T-Invest; не привязывать доменную модель к protobuf DTO.

## Порядок

`M0` уточнение источников/контрактов → `M1` read-only импорт и история → `M2` учёт акций/денег → `M3` фьючерсы/маржа → `M4` сверка → `M5` UI/отчёты → `M6` привязка роботов → `M7` execution analytics → `M8` риски/портфели → `M9` исследовательский слой → `M10` ML → `M11` остальные брокеры/плагины. Подробные критерии в roadmap.

**Предупреждение:** первый CLI прототип создан, но не подключён к реальному счёту и не проверен на брокерской истории. Промежуточные денежные суммы не являются полным P&L портфеля. См. [11-implementation-status.md](docs/11-implementation-status.md).
