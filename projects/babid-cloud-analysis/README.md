# Babid Cloud — независимый офлайн-анализ торговли

Это **отдельный исследовательский проект внутри Analytics**, а не модификация торгового робота.
Исходная программа и её журналы служат **входными данными только для чтения**. Здесь находятся
только аналитические Python-скрипты, тесты с вымышленными данными, документация и CI.

## Назначение

- Обнаружение дублирующихся каталогов состояния и журналов в копиях конфигурации.
- Поиск ошибок работы робота: остановки Risk/Halted, дублирующие и пропущенные исполнения,
  отклонения заявок, реконнекты и расхождения позиций брокера и журнала.
- Сверка `fills.csv` с `journal.json` с точными десятичными вычислениями.
- Оценка P&L по дням с отделением realized от mark-to-market и предупреждением о комиссиях.
- Анализ рыночных записей `.tsv`/`.tsv.gz` и проверка доступности котировок в стакане.
- Описательное сравнение параметров на разных днях, с последним днём вне обучающей выборки.

**Ограничение:** доступность котировки не равна вероятности исполнения и не является
прогнозом прибыли. Реальные комиссии, funding и проскальзывание нельзя восстановить
только из внутренних журналов робота. Бэктест исполнения через движок ещё не реализован.

## Где работать

Все разработки и GitHub Actions **только в `IskanderAbdullin/Analytics`**,
в каталоге `projects/babid-cloud-analysis`.
Внешние репозитории и работающая программа не изменяются.
В GitHub не загружаются реальные журналы, брокерские токены, конфигурации,
снимки состояния и отчёты с торговыми идентификаторами.

## Проверки (стандартная библиотека Python 3.11+)

```bash
cd projects/babid-cloud-analysis/analysis
python -m compileall -q .
python -m unittest discover -p "test_*.py" -v
```

GitHub Actions выполняют только эти проверки на Ubuntu и Windows, без секретов
и без обращения к каким-либо другим репозиториям.

## Анализ истории на локальной копии

Внешнюю папку с копией робота передавай как `--root`. Результат сохраняется
в новом, ранее не существовавшем подкаталоге `<КОПИЯ>/reports/`.
Скрипты не умеют отправлять брокерские заявки, изменять конфигурацию или
вмешиваться в запущенный процесс.

```bash
python run_offline_audit.py --root "<PATH_TO_COPIED_BABID_CLOUD>"
```

Для быстрого прогона без записей рынка:

```bash
python run_offline_audit.py --root "<PATH_TO_COPIED_BABID_CLOUD>" --skip-market
```

Полные журналы могут занимать сотни мегабайт; скрипты читают их потоково.
В результатах проверяется неизменность источников, но это **не** эквивалент
атомарного снимка файловой системы.

## О статусе

Исходные аналитические утилиты перенесены в отдельный проект и теперь имеют
собственное синтетическое CI. Реальные журналы и сделки пользователя в
публичном репозитории отсутствуют. Исходную причину расхождения NVDA на 2 лота
нельзя доказать без локальной обработки полной истории и сверки с брокером.

## Полная проверка связки анализаторов

Кроме отдельных тестов доступен `analysis/test_integration_pipeline.py`, который
создаёт исключительно **синтетический архив** конфигурации, журнала,
исполнений, P&L и сжатой записи рынка, затем пропускает его через весь
`run_offline_audit.py`. Проверяется согласованность всех отчётов,
отсутствие записи в исходные файлы и запрет повторного использования
каталога результатов. Никаких реальных торговых данных в CI нет.

## Качество и полнота биржевой записи

Дополнительная команда:

```bash
python tape_integrity.py --root "<PATH_TO_COPIED_BABID_CLOUD>"
```

Потоковый парсер точно следует `MarketRecording.cs` версии `855745b...`:
`B recvMs exchangeMs bids asks`, `T/G recvMs tradeMs ...`, `D/U` — разрывы
канала; метка `I` хранит инструмент. В журнал выводятся количество
повреждённых и пересечённых стаканов, задержка `recvMs-exchangeMs`,
обратные временные метки, восстановленные сделки, известная длительность
разрывов потока и незавершённые разрывы.

Важно: робот не записывает **неизменившийся** стакан, поэтому большой
промежуток между строками `B` сам по себе **не доказывает** потерю данных.
Вычисляемая разность временных меток не является чистой сетевой задержкой.
Скрипт не выполняет сделок, не меняет состояние робота и не называет
«лучшую» настройку без верифицированного исполнения.


## Offline markout после исполнения

Модуль analysis/execution_markout.py вычисляет для каждого исполнения из
fills.csv наблюдаемую среднюю цену стакана через 5 и 30 секунд. Пример:

    python execution_markout.py --root "<PATH_TO_COPIED_BABID_CLOUD>" --state state-nvda-iis-live --instrument NVDAperpA --day 2026-11-21

Время сделки в fills.csv — МСК (время сделки брокера). Стакан имеет время
получения UTC Unix ms. Используются только стаканы, полученные строго ДО
момента измерения; запрещены look-ahead, устаревшие снимки и переходы через
разрывы потока. По умолчанию максимальный возраст снимка 2000 мс.

Положительный markout означает сдвиг цены в выгодную сторону относительно
сделки; отрицательный — в невыгодную. Это НЕ реализованная прибыль, не прогноз,
не оценка комиссии, финансового тика или вероятности исполнения. Исследователь
явно указывает state/instrument/day, так как окончательный JSON-конфиг не
доказывает историческую принадлежность всех исполнений. Отчёты с trade_id
хранятся только локально и не публикуются.
